## Audit basis and guardrail

This is a module-level alignment audit of the **live Canvas course 23402**, retrieved on 2026-08-19. The source snapshot contains 34 modules and 391 ordered module items. It identifies the TEKS that the current student work can support; it does not yet add or change a Canvas page.

Use the [canonical Grade 8 TEKS transcript](texas-technology-applications-grade-8-teks-2022.md) for exact wording. This ledger intentionally names only codes so the formal wording can be inserted verbatim when a teacher guide is updated.

**Key:** `D` = demonstrated by the named product or performance; `P` = practiced with visible evidence; `I` = introduced only; `Optional` = only claim the alignment when the optional route is assigned; `N/A` = do not claim Grade 8 Technology Applications alignment for the current module as a whole.

## Important audit findings

1. **Do not use §126.19(c)(2)(B) as a generic coding tag.** That grade-level expectation specifically requires text-based programs with nested loops. The live VILS pages reviewed here do not consistently make that evidence explicit. It can be added only to a lesson that actually requires and checks it.
2. **Module 19 is a real coding sequence, but much of the named work is block coding.** The audit therefore records it as practice for debugging and code revision, not as a blanket Grade 8 text-based-programming claim.
3. **Modules 9 and 6 are optional.** Their TEKS block must visibly say “optional route—only when assigned.”
4. **Module 27 is intentionally project-dependent.** Its guide needs one general design-process alignment plus a per-capstone-route TEKS selection; a single all-purpose TEKS list would be misleading.
5. **Module 29 has no facilitator guide.** It needs a new guide before it can achieve teacher/site parity. Module 34 is parked and should remain unclaimed.
