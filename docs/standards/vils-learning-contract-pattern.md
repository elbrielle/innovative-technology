# VILS Learning Contract and TEKS Alignment Pattern

## Purpose

Use this pattern to make every active VILS instructional module legible to a student, a teacher, and an administrator without turning a student assignment into an audit report.

The Grade 8 Technology Applications source of record is [Texas Technology Applications, Grade 8 TEKS](texas-technology-applications-grade-8-teks-2022.md). A TEKS code may be claimed only when the student work actually supplies the named evidence.

## Student-facing learning block

Place one concise block at the beginning of the module hub or first core student learning page. It should help students understand today's work, not require them to interpret state-rule language.

| Field | Rule | Example shape |
| --- | --- | --- |
| **Big Question** | One genuine, answerable question when the lesson has a conceptual tension worth carrying. Omit it when it would be decorative. | How can a system make a useful decision without making the decision for us? |
| **Topic** | Three to five words. | Image classification and bias |
| **Objective** | One student-facing sentence, scoped to the particular lesson rather than copied from a TEKS statement. Use “I can” language when that suits the page voice. | I can test an image model with varied examples and explain one reason its result may be unreliable. |
| **Show Your Learning** | Name the exact product or response the student submits, including the observable parts that matter. Keep this concrete enough that a student can self-check. | Submit a test log with results from three varied examples and a two-sentence claim about what the model needs to improve. |

Do **not** place a long TEKS list in the student block. If a classroom wants the standards visible to students, use one plain-language “Standard focus” sentence derived from the aligned expectation; keep the official codes and full legal wording in the teacher guide.

## Teacher/facilitator-guide alignment block

Place this block near the top of every active facilitator guide, after the opening context and before preparation or teaching moves. It is the administrator-facing record and must contain the evidence claim.

| Field | Required content |
| --- | --- |
| **Topic** | The same short topic used in the student block. |
| **Student objective** | The same scoped objective, written as “Students will …” if the guide's voice calls for teacher framing. |
| **Essential TEKS** | The one or two central §126.19(c) expectations. Show each full code and exact official wording. |
| **Supporting TEKS** | Only additional expectations students genuinely practice in this lesson or module. Show each full code and exact wording. |
| **Demonstration of learning** | The submitted or observed evidence, plus the success condition that shows the TEKS is more than a topic mention. |
| **Alignment status** | `introduced`, `practiced`, or `demonstrated`. A module cannot be called demonstrated merely because the vocabulary appears. |

Use this label order in Canvas and in the generated public guide:

```text
Instructional Alignment
Topic:
Student objective:
Essential TEKS:
Supporting TEKS:
Demonstration of learning:
Alignment status:
```

## Scope rules

1. **Module and lesson levels are different.** A main module guide gets a concise module-level record. Where a module has separate lesson guides, each guide receives only the specific TEKS and evidence for that lesson; it does not inherit the entire module list.
2. **Optional, enrichment, and parked work stay honest.** Label an optional route as optional. Use `not applicable` where there is no defensible Grade 8 Technology Applications evidence rather than adding a cosmetic code. Parked alternatives receive no active compliance claim.
3. **One aligned standard is stronger than a long list.** Essential means the student could not complete the named demonstration without engaging that expectation. Supporting means the evidence shows real practice, not merely tool use.
4. **The standard's wording stays exact.** The source record supplies the legal text. Objectives and demonstrations may be written in course language, but are not substitutes for the official expectation.
5. **No duplicate curriculum source.** Canvas is the authoring source for the guide. The public site is regenerated after the Canvas change; do not hand-edit generated lesson or module pages to create the appearance of parity.

## Audit deliverable

The alignment audit should produce one record for each active VILS module and, where present, each lesson-level facilitator guide:

| Module or guide | Active/optional/parked | Topic | Objective | Essential TEKS | Supporting TEKS | Demonstration of learning | Status | Evidence location |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |

The audit must explicitly identify pages that have no current facilitator guide. In the latest local course snapshot, **Stop Motion** and **Parked Alternates** fall into that category; neither should quietly disappear from the review.

## Publication workflow

1. Audit the live Canvas source and write the alignment records against actual student evidence.
2. Add the student learning block to the selected student-facing hub/first-core page and the full alignment block to the matching facilitator guide.
3. Re-export Canvas and regenerate the public site.
4. Verify that the Canvas teacher guide and the public facilitator-guide page carry the same topic, objective, TEKS codes, and demonstration of learning.
5. Review desktop/mobile rendering, accessibility, links, and the active/optional/parked labels before publication.
